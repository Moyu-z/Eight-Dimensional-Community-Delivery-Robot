# 需求说明书

**项目名称**：基于 Unity 的八维通未来社区智能配送机器人虚拟仿真软件  
**文档版本**：v1.0  
**日期**：2026-11-08  
**适用阶段**：毕业设计开题 / 场景基线 / 寻路功能开发前

## 1. 项目背景与目标

未来社区通常包含住宅、商业、医疗和公共服务等多种功能，配送机器人在楼宇、道路与人流之间运行，需要兼顾路径效率、安全性和任务可达性。本项目使用 Unity 建立未来社区虚拟仿真沙盘，为配送机器人的路径规划、任务调度和运行验证提供可重复、可观察的实验环境。

项目目标：

1. 构建一个布局清晰、可扩展的未来社区三维沙盘。
2. 覆盖住宅、商业、医疗三类典型配送目的地。
3. 为配送机器人提供可导航的道路、人行道、楼宇入口和停靠区域。
4. 支持后续接入机器人模型、NavMesh 寻路、任务状态机和运行数据可视化。

## 2. 使用对象与场景

- **学生 / 开发者**：在 Unity 编辑器中搭建、调整和验证场景。
- **答辩评委**：通过主相机或运行演示观察社区全貌、配送路线和任务流程。
- **后续仿真程序**：以场景中的道路、建筑和锚点为输入，执行路径规划与配送任务。

## 3. 核心功能需求

### FR-01 未来社区沙盘

- 建设三个相邻的 100 × 100 m 地块，整体形成约 200 × 200 m 的 L 形社区。
- District_01 为住宅区，包含住宅楼、低矮商业配套和社区配送站。
- District_02 为商业科技区，包含蓝色玻璃板楼、银色商业综合体和空中连廊。
- District_03 为医疗区，包含 T 字路口和大型医院综合体。
- 道路、人行道和地面在相邻地块边界处必须连续，不能出现可见断层。
- 场景应支持高层俯瞰，便于答辩时展示整体布局。

### FR-02 T 字路口与大型医院

- 主干道在 District_03 的 Z = 100 处与横向道路相交并终止，形成 T 字路口，不再向北延伸。
- 医院位于 T 字路口后方，主楼为白色，占地宽大，屋顶设置醒目的红十字。
- 医院应包含明确的入口、落客区域和病房窗带等可识别要素。
- 医院与商业区之间应通过绿化带、绿篱或围墙进行空间隔离，仅保留道路出入口。
- 医院和商业区之间需保持足够距离，避免医院后勤、急救流线与商业人流互相干扰。

### FR-03 社区配送站

- 配送站位于 District_01 东南侧靠近路口的位置，作为机器人任务的起点和终点。
- 配送站应具有醒目的颜色、发光标识和可识别的入口台阶。
- 设置机器人停靠圆盘、充电桩和入口锚点，供后续导航直接引用。
- 配送站入口锚点应位于广场可达区域，不能与建筑碰撞体或台阶重叠。

### FR-04 配送机器人寻路

- 使用 Unity AI Navigation（NavMesh）为三个地块烘焙可行走区域。
- 机器人应能从配送站出发，到达住宅楼入口、商业综合体入口和医院入口等目标点。
- 支持静态障碍物避让（建筑、台阶、绿化带、围墙、路灯基座等）。
- 支持至少一次路径重规划：目标点变更或路径被阻挡时，机器人能够重新计算路线。
- 配送任务应具备基本状态：待命 → 取件 → 运输 → 到达 → 返回/待命。
- 运行过程中应可视化当前路径、目标点和任务状态，便于演示与调试。

### FR-05 视觉与交互

- 住宅区、商业科技区、医疗区应具有明显不同的建筑风格和材质语言。
- 商业区使用蓝色半透明玻璃与银色金属；医疗区使用白色主楼和红色十字标识。
- 场景应配置主相机、主光源和补光，保证白模体块和玻璃材质可读。
- 后续应提供基本的运行 HUD 或任务面板，显示机器人状态和当前配送目标。

### FR-06 MCP 与 AI 辅助开发管线

- 项目应保留 MCP 自动化开发管线，用于 Unity 场景读取、对象创建、布局校验和批量修改。
- DeepSeek Harness 作为 AI 辅助工具，用于脚本生成、代码检查、文档整理和重复性操作。
- 核心场景结构、关键功能代码和最终交互逻辑必须由开发者理解、维护并能够完整讲解。
- 第三方开源框架、插件和素材需在文档中标注来源，并完成必要的自主改造。

## 4. 非功能需求

- **性能**：在答辩演示机上保持稳定帧率，目标 30 FPS 以上，交互场景目标 60 FPS。
- **可维护性**：场景对象按功能分组，建筑、道路、绿化、路灯和站点命名清晰。
- **可复现性**：主场景可通过 Unity 打开；程序化生成器应能重复生成基础白模。
- **版本管理**：使用 Git 记录开发过程，提交信息清晰，保留阶段性提交记录和截图。
- **兼容性**：Unity 6000.3.9f1 + URP；Windows 平台优先。
- **文档完整性**：README、需求说明书、开发日志、测试记录和答辩材料保持同步更新。

## 5. 验收标准

1. 打开 `Assets/Scenes/FutureCommunity_Blockout.unity`，可以完整看到三个地块及主要建筑。
2. District_01 / District_02 / District_03 的道路、地面和人行道接缝无可见断层。
3. T 字路口形态正确，医院位于路口后方，屋顶红十字清晰可见。
4. 配送站、入口台阶和机器人停靠锚点位置正确，无穿模。
5. 商业区板楼、天桥和银色商业体风格与住宅区有明显差异。
6. NavMesh 烘焙完成后，配送站到至少三类目的地均存在可行走路径。
7. 机器人能够完成一次完整配送流程，并在演示中显示路径和任务状态。
8. 仓库包含 README、需求说明书、开发日志和阶段性提交记录。

## 6. 当前范围说明

当前已完成三个地块的白模、道路网络、建筑体块、配送站和医疗区隔离带，属于**场景与空间基线阶段**。配送机器人模型、NavMesh 烘焙、寻路算法、任务状态机和运行 HUD 尚未完成，将在后续迭代中实现。

## 7. 主要约束与风险

- 场景体块和第三方素材需要在软著申报前确认原创性与授权来源。
- 玻璃透明材质和大量独立体块可能带来渲染开销，需要在性能测试阶段合批或简化。
- NavMesh 需要处理台阶、绿化带、围墙和建筑入口的高差，避免机器人在视觉上“穿墙”或卡住。
- AI 辅助内容需保留人工修改记录和设计说明，确保答辩时可以解释核心实现。
